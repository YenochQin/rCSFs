## 结论

1. **尾部（转换+写出）提速 2.36–2.47×**（B1 8.536 → 3.450 秒，B2 2.575 → 1.090 秒），
   达到 P4 的"并行转换阶段至少 2×"目标；端到端 B1 9.263 → 5.819 秒（−37.2%），
   B2 2.914 → 2.218 秒（−23.9%）。
2. **累计相对基线 `7ad18b1` 的 8 线程达到 2× 以上**：B1 14.403 → 5.819 秒（**2.47×**），
   B2 4.825 → 2.218 秒（**2.18×**）。开 zstd 时为 2.26× 与 1.91×（B2 略低于 2×）。
   这是本机、本输入、默认去重策略下的结果，不外推到目标机器。
3. **编码阶段成为尾部最大单项**（B1 1.387 秒、B2 0.655 秒，CPU≈墙钟）：这正是未实施的
   "并行 Parquet 列块编码"所指向的收益点。计划中该项标注为未实施是因为当前 `parquet`
   crate 没有受支持的并行入口；本测量给出了投入它的量化理由，但实现它需要自建编码器
   与 footer 重建，属独立决策。
4. zstd 的代价在单遍尾部下基本不变（B1 +9.5%、B2 +13.8%），因为它现在只在 prepare
   阶段解压一次，而不是两遍尾部时的两次。

## 未测量与边界

- 目标机器与目标文件系统；本机 NVMe/APFS、页缓存未清空，macOS 无 `process_io`，
  因此没有物理 I/O 与写放大数字。
- 线程数扫描：本轮只测 8 线程。P4 完成条件中"线程数变化不改变 CSF 字节及 V2 行"由
  Rust/Python 差分测试覆盖（`o1` 的逐字节比较、`prefix_split_transcript` 的逐行比较），
  本机尚未做 1/2/4/8 线程的字节对照测量。
- 发布路径：流水线内部（暂存→发布）已是 rename 语义并含竞争写入测试；CLI 从 staging
  到目的地的复制、部分发布失败策略仍是 P4 未实施的子步骤，本页不含其数字。
