## 计数结果

| 指标 | 本报告 | §2.2 登记值 |
| --- | ---: | ---: |
| 唯一占据组态 | 7,031,941 | 7,031,941 |
| 去重前 CSF（计数） | 5,814,175,207 | 5,814,175,207 |
| Peel 子壳层 / V2 列数 | 56 / 226 | 56 / 226 |

三项都与 §2.2 由独立动态规划得到的数值完全一致。这是对计数实现最有力的一次对照：它覆盖 703 万个组态，说明基于累积 2J 的动态规划在真实规模上复现了生成语义，而不只是在小样例上成立。

调度结果：1,455 个任务，任务规模目标 4,000,000 条（由计数总量与线程数推导），每任务估计记录数的 p50 为 3,999,089、p95 为 3,999,953、最大 3,999,999；14,185 个组态预计不产出任何 CSF；没有不可拆分的长尾（0 个任务超过目标）。旧的固定 4096 组态切分在同一次运行中会产生 1717 个任务，且单个任务的中位与长尾分别约 193 万与 3038 万条。

## 容量估算

模型只依赖计数值与 Peel 列数，各比例的来源与误差见报告中的 `assumptions` 与下表。

| 路径 | 估算 | 说明 |
| --- | ---: | --- |
| Arrow segment | 5.85 TB | 未压缩，含 10% 帧开销；§2.2 按 916 B/行得到 4.844 TiB = 5.33 TB |
| 根去重桶 | 5.58 TB | 每行 V2 载荷 + 24 B + 32 B 帧；§2.2 得 4.907 TiB = 5.40 TB |
| 递归桶（假设一层） | 5.58 TB | 未实测，按最坏情况各写一遍 |
| 幸存位图 | 0.73 GB | 每条唯一记录 1 bit |
| **scratch 峰值** | **17.0 TB**（含余量 19.4 TB） | segment + 根桶 + 递归桶 + 位图 |
| 描述符 Parquet | 13.1 GB | 0.01 B / 列 / 行 |
| CSF 文本 | 1.87 TB | 321 B/记录 |
| CSF Parquet | 424 GB | 73 B/记录 |
| **发布产物合计** | **2.30 TB**（含余量 2.88 TB） | 发布是复制，产物与 staging 同时存在 |

不受递归桶假设影响的口径是 11.4 TB scratch 峰值（含余量 13.1 TB）；递归桶占比最大，它是唯一未被实测的项，模型按"再整体重写一遍"计入。写放大因此在 2.0×（不含递归）到 3.0×（含递归）之间，相对最终产物 2.30 TB 则约为 5–7×。

本机可用空间 73 GB，产物本身就需要 2.88 TB，因此预检在写入任何 segment 之前即拒绝该运行。这正是 P1.5 想要的效果：不可完成的运行不应该先写几小时再失败。

## 时间区间（外推，非承诺）

按 B1 在 8 线程下各阶段的实测每记录速率外推到 58.14 亿条：

| 阶段 | B1 每记录 | 外推 |
| --- | ---: | ---: |
| 生成 | 0.45 µs | 0.7 h |
| 去重 | 1.61 µs | 2.6 h |
| 合并描述符 | 1.09 µs | 1.8 h |
| 文本与 CSF Parquet 还原 | 2.11 µs | 3.4 h |
| 合计 | | **约 8.5 h** |

这是乐观下界，必须按区间理解：B1 只有 270 万条、scratch 峰值 2.1 GiB，页缓存能容纳大部分中间数据；完整输入的中间数据是 TB 级，去重与还原阶段的随机读会明显变慢。计数与规划本身已实测为 23 秒，可忽略。
