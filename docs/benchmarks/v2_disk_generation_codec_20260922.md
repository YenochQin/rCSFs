# P2a：临时 segment 的 Arrow IPC 压缩实验（2026-09-22，47e04ea 复测）

本文登记 [CSF_V2_GENERATION_PERFORMANCE_PLAN.md](../CSF_V2_GENERATION_PERFORMANCE_PLAN.md)
P2a 的限时实验：临时 Arrow IPC segment 不压缩、LZ4_FRAME、ZSTD 三者的耗时、写入量、
CPU、受管内存与进程 RSS。这是决策实验，不是长期架构投入。

## 两轮测量与复测原因

第一轮（提交 `3588df1`，扩展 `cbcf2eb8…`，报告见该提交的 git 历史）在**精确去重**还是
唯一路径时测量，结论是"zstd 优于 lz4"：当时**两个**读取阶段（去重与合并）都要解压
segment，zstd 较快的解压占了上风。P6b 之后默认路径不再写根桶、不再有去重读取，只剩
**一个**解压点（合并），该结论的依据消失，且旧 harness 的 RSS 是共享进程的单调高水位、
没有产物内容摘要。本页是 `47e04ea` 上的复测：默认走 verified_unique 路径，每次测量在
独立进程中运行（RSS 为单次测量的高水位），并在计时区外记录四个发布产物的 SHA-256。

测量来自**干净工作树**的提交 `47e04ea`（tree 与扩展 SHA-256 `2e793429…` 记录在 JSON
的 `environment.git.tree` 与 `environment.extension.module_sha256` 中，可重建后比对）；
Apple M4 10 核 16 GiB，APFS；8 线程；每个 codec 预热 1 次后测量 3 次，codec 之间顺序
执行（`none → lz4 → zstd`），表中为中位数。

原始报告：
[codec b1](v2_disk_generation_codec_b1_20260922.json)、
[codec b2](v2_disk_generation_codec_b2_20260922.json)。

B2 的 zstd 组单次为 3.315 / 4.046 / 6.190 秒（6.190 为离群值），表中取中位数；
其余各组单次极差 ≤ 0.27 秒。受管内存峰值与 codec 无关（B1 62.0 MiB、B2 130.4 MiB，
三个 codec 完全相同）：压缩发生在 Arrow 写入器内部，不占用受管预算。发布产物内容与
codec 无关——[dedup 报告](v2_disk_generation_dedup_20260922.md)记录的 SHA-256 在
`none` 与 `zstd` 下完全相同。

## 结论

1. **segment 字节压缩 43×–112×**（B1：1073.0 → 25.0/11.7 MiB；B2：506.0 → 8.2/4.5 MiB），
   与第一轮一致——压缩比是数据（密集 Int32、大量 `MISSING`、低基数字段）的性质，不是
   去重路径的性质。它说明"临时 Arrow 不值得按未压缩体积规划"，不说明任意输入都能达到
   同样倍数。
2. **codec 的全部代价在合并阶段的解压**（唯一的读取点）：B1 合并由 2.846 秒升至
   4.289（lz4）/ 3.507 秒（zstd），B2 由 1.388 升至 2.094 / 1.984 秒。写入侧生成阶段
   基本不变，唯一例外是 B2 的 zstd（0.265 → 0.392 秒）：226 列宽行的压缩本身开始计费。
3. **第一轮"zstd 优于 lz4"的结论依据已消失，但本机样本不足以给出新的单向结论**：
   剩一个解压点后，B1 上 zstd 明确更快（9.944 对 10.633 秒）；B2 上 zstd 的中位数
   （4.046 秒）被一次 6.190 秒离群抬高——其预热与最快单次为 3.23 / 3.315 秒，低于 lz4
   的全部单次（3.665–3.691），且 zstd 的合并解压也更快（1.984 对 2.094 秒）。zstd 付的
   是写入侧（生成 0.265 → 0.392 秒）与**单次波动**（B2 极差 2.87 秒，lz4 仅 0.03 秒）。
   若为省空间启用 codec，取舍应在目标机器上以更多样本重测；本机三样本不足以裁决 B2。
4. **压缩 codec 的 RSS 更低而不是更高**（B1 250.6 → 230.0/234.4 MiB，B2 395.3 →
   346.6/338.3 MiB，中位数）：更小的写出缓冲与流式解压抵消了压缩器本身的开销；受管
   内存完全不变。
5. **默认保持不压缩**：端到端典型代价约 +6%（B1 zstd 中位）到 +10–23%（B2，视离群
   处理），换取 scratch 从 segment 未压缩量降到压缩量。启用与否是空间对时间的取舍，
   应由 P6b 之后的 B4 容量决策在目标机器上做，不在本机预先定死。

## 未测量

- 目标机器与目标文件系统；本机 NVMe/APFS、页缓存未清空，`process_io` 在 macOS 上
  不可得，因此表中没有物理 I/O 与写放大。
- 其他压缩级别：`arrow-ipc` 使用 LZ4_FRAME 默认参数与 zstd 默认级别，未做级别扫描
  （B2 的写入侧代价提示级别扫描可能有用）。
- B3 规模：该实验只跑了 B1/B2，因为 P2a 是限时决策实验。
- 根去重桶与递归桶的压缩：verified_unique 路径下已不写根桶，本项只对 `exact` 路径
  有意义，未测。
