状态：已完成生成与文件兼容性检查，未运行 SCF/RCI。未修改生成器生产代码。

## 目的、输入和判据

验证 rCSFs 首版直接 CSFG 生成器能否复现 `graspg/graspgtest` 中的实际生成模型，
并覆盖脚本的逐层活性空间，而不只验证此前的 Gd 单例。
预期是相同物理模型下生成的 `.g/.l` 文件一致；判据为字节相同及每个 Jπ 块的精确记录比较，
不使用能量容差，也不把总数量相同作为充分条件。

- 原始 GRASPG 源码及脚本提交：`e157d9fc61e8d2882e0b29d644b2bb011f5f745d`。
- 从原 Makefile 对象清单提取未修改的生成源码，在独立临时目录编译原版
  `rcsfggenerate_csfg`、`rcsfgsplit_csfg`、`rcsfgexpand_csfg`。
- 编译器：`GNU Fortran (GCC) 16.2.1 20260810`；选项 `-O3 -fno-automatic -fallow-argument-mismatch`。
- rCSFs：基线 `4e57b463f6ad1599fdc5a6a27bf7e0c6c933eff6` 加本地未提交实现，安装到本仓库环境的开发 wheel。
  测试调用真实 `rcsfs csfggenerate` CLI，禁用 `PYTHONPATH` 覆盖，指定 8 线程。
- 本轮 native extension SHA-256：`21471326f28b710016c03dc6665c2b1d560266771631f5d59eab3e640602e758`。
- 逐份记录原脚本 SHA-256；测试结束复核全部未变。没有在原测试目录执行清理或写入。

## 输入覆盖与必要适配

扫描得到 **20 次 `rcsfggenerate_csfg` here-doc 调用**，去重为 **10 组输入**。
`script3_ZF` 的生成输入复用 script2/3 的 MR、VV 与全相关模型；
`script5` 的生成输入与 script4 CI 相同。参考生成器只编译一次，每种不同输入执行一次；重复调用以输入映射记录。

适配规则限定于此次明确检查过的脚本：

1. 第一个列表的轨道范围作为 `labeling_space`。
2. 后续 SD 列表包含初始零激发 MR 时，检查参考占据与 J 范围的包含关系后，按 SD 物理模型生成；
   共同范围与共同 J 区间的参考列表合并为一个 `reference_configuration` 数组。
3. case05/06/07 的偶宇称请求 2J=0..6、奇宇称请求 2J=0..4。
   rCSFs 当前没有原生的“每列表不同 J”接口，因此分别进行两次生产 CLI 调用，再由测试工具
   合并**不重叠**的 Jπ 块。合并时要求 header 与 rlabel 一致，不改变块内记录顺序，不进行记录过滤。
4. 这证明这些脚本模型可通过该适配复现，**不表示原生多列表接口已经实现**，也不是对任意 Fortran 输入的通用转换器。

## 结论与边界

- 共执行 57 次生产 Rust CLI 请求，完成 10 组原始输入和 32 个直接分层检查，未发现生成差异。
- script3_ZF 中的相互作用筛选和零/一阶重排是后处理，不属于此次生成器比较。
  其原始生成调用已经覆盖，但没有将筛选后的 `Zero_n/Full_n` 文件当作原始生成结果比较。
- 没有执行整份 `run.sh`、核数据生成、角向矩阵、SCF、RCI、跃迁或集群作业。
- 本结论针对该源码版本和列出的输入。不同相关范围的任意多列表、三重激发、任意径向例外及物理收敛不在本次验证范围。
