## 结论

1. **跳过精确去重链路把 B1 从 13.747 秒降到 9.287 秒（−32.4%），B2 从 4.832 降到
   2.971 秒（−38.5%）**；省下的全部落在去重阶段本身（B1 4.549 → 0.005 秒，B2
   1.683 → 0.001 秒），生成、合并、还原三段在两种策略下相同。按计划要求，这一项单列，
   不冒充其它阶段的加速。
2. **scratch 峰值下降约 50%**（B1 2142.5 → 1073.3 MiB，B2 1001.9 → 506.1 MiB），
   减少的正是根桶：去重阶段的临时写入从 1069.8 MiB 降到 0.3 MiB（B1）、496.0 降到
   0.1 MiB（B2）。剩下的 0.3/0.1 MiB 是幸存位图本身——merge 仍按发布顺序读取它。
3. **组合配置把 scratch 压到 segment 量级**：verified_unique + zstd 时 B1 scratch
   峰值 12.0 MiB（相对 exact+none 的 2142.5 MiB 减少 99.4%），B2 为 4.5 MiB
   （相对 1001.9 MiB 减少 99.6%）。这正是重新表述后的 P2b 验收条件所要求的形态。
4. 组合配置的端到端代价是 zstd 的解压：B1 9.287 → 9.784 秒（+5.4%），B2 2.971 →
   3.284 秒（+10.5%），全部出现在合并阶段（2.814 → 3.508、1.397 → 1.720 秒）。
5. 相对计划基线 `7ad18b1` 的 8 线程（B1 14.403 秒、B2 4.825 秒），组合配置为 9.784 秒
   （B1，−32%）与 3.284 秒（B2，−32%）。P4 的"累计 ≥2×"仍是未达成的调研目标，剩余
   空间在合并/还原两段（B1 合计 9.1 秒）。

## 未测量与边界

- 目标机器与目标文件系统；本机 NVMe/APFS、页缓存未清空，macOS 无 `process_io`。
- 递归分桶：两种输入都没有触发（根桶行数远低于叶桶上限），因此"跳过根桶"节省的是
  根桶那一轮写入/读取，递归层从未参与。
- 已验证路径的正确性依据是 [V2_GENERATION_UNIQUENESS.md](../V2_GENERATION_UNIQUENESS.md)
  的证明与 `tests/p6a_*` 的穷举；本页只是它在真实输入上的差分与计量。
- 反例形态（同一 segment 被排两次）在本页的输入中不可达，它由
  `a_repeated_segment_is_only_removed_by_the_exact_path` 单测覆盖：那种输入下两条
  路径确实不同，因此快速路径的适用范围来自构造，而不是来自"没见过重复"。
