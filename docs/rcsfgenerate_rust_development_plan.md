# CSF 内存表示与 Rust 并行生成器开发计划

## 1. 目标与边界

面向至少配备 128 GB 内存的服务器，将当前 `rcsfgenerate` 的“枚举、文本落盘、反复合并去重、重读分块”流程，重构为：

```text
读取生成输入及轨道定义
    → 枚举符合参考组态限制的相对论占据
    → 内存中合并重复生成任务
    → 并行生成完整整数 CSF 表示
    → 按原版最终顺序组织结果
    ├→ 一次输出 GRASP CSF 文本
    └→ 派生现有 ML 描述符 → 可选归一化
```

核心要求：

- 与固定版本的原版 Fortran 保持 CSF 内容、数量、对称性分块和最终顺序一致。
- 保留 seniority 等区分子壳层态所需的信息，整数表示可以还原合法的 GRASP CSF 文本。
- 支持单一 J 下的大规模并行，不依赖多个 J 才能利用多核。
- 默认在内存中保存过程和结果，生成阶段不使用巨大的 CSF 文本中间文件，不采用两遍耦合枚举作为默认方案。
- 保留现有 rCSFs ML 描述符接口；完整 CSF 表示是新增的权威数据模型。
- 本文档只规划开发，不代表性能或等价性已经得到验证。

## 3. 已确认的源码事实

- `grasp/src/appl/rcsfgenerate90/wrapper.f90` 调用输入处理与生成流程：先 `rcsfexcitation`，再 `jjgen15`。
- `rcsfexcitation.f90` 是交互前端，把用户回答改写成 `jjgen15` 消费的低层输入流（unit 11），并把可复现记录写入 `rcsfgenerate.log`（unit 12）。登记 fixture 是后者的格式，因此若从 fixture 出发，必须自己承担 `rcsfexcitation` 的全部改写规则，详见 §3.1。
- `jjgen15b.f90` 按模式分派：`*` 新建列表走 `matain` + `blanda`；`e` 扩展已有列表走 `adder` + `matcin` + `blandc`；`a` 追加到已有列表走 `adder`，但其提示已在 `jjgen15b.f90:64` 注释掉，正常交互无法到达。
- `blanda.f90` 枚举符合限制的占据，在合法占据处调用 `GEN`。送入 `GEN` 前施加参考宇称判据 `par == par0`（`blanda.f90:1411-1421`，`par0` 见 `:82`），因此一个参考组态只产生与自身同宇称的 CSF。
- `slug.f90` 给出每个 slot 的占据上下界：`start = min(minmax, org+(varmax-varupp))`、`stopp = max(low, org-(varmax-varned))`。`varmax` 只是上界，单激发与多激发同时包含在内。`slug.f90:56-60` 对 `l >= 5` 将 `minmax` 压到 4，而非 `2+4l`。
- `genb.f90` 中的 `GEN` 枚举子壳层态和角动量耦合，调用 `KOPP1/KOPP2` 格式化，并直接写文件、累计数量。
- `blandc.f90` 是扩展模式的独立枚举路径，内部调用 `blandb` 与 `mergeb`，并以 `lista(15000,15,0:10)` 保存已有列表的占据，存在 15000 条硬上限。它不是新建路径的参数化变体。
- `matbin.f90:47` 在每轮生成后询问 `Generate another list? (y/*)`；回答 `y` 会让 `jjgen15b.f90:104-121` 带着 `second=.TRUE.` 再跑一轮 `blanda` 与 `merge`。单份输入记录可以包含多个依次生成并合并的列表。
- `reffa.f90:33-96` 按 `*`/`r`/`s`/`u` 决定 `posn/posl`，即耦合与子壳层顺序；`u` 需要外部文件 `clist.ref`。该选择直接改变输出的子壳层顺序和耦合链。
- `merge.f90` 通过占据比较进行流式合并；相同占据时跳过第二份相应的整组 CSF。当前并非把整个文本文件一次加载到内存，但存在反复读取和重写。
- `rcsfblock.f90` 的当前路径重读结果并按对称性分块，不承担该路径的去重。
- `matcin.f90:67-71` 把 `lima` 硬编码为 `.FALSE.`（源码注释：该选项无法正确运行，暂不提供），因此 `lim(15)` 的 n 壳层电子数下限在原版中是死代码，`blanda.f90` 中所有 `antel(i,j) < lim(i)` 分支永不触发。Rust 侧不实现是正确的。
- rCSFs 当前描述符为每个轨道的 `[占据数, 2J_子壳层, 2J_累积耦合]`。解析分号字段时丢弃分号前的 seniority，因此未归一化描述符也不是无损表示。

开发开始时应依据固定提交重新确认这些位置，追踪其他输入分支、调用者和辅助输出契约，不能仅迁移普通新建列表路径就宣布全功能等价。

### 3.1 `rcsfexcitation` 的输入改写规则

登记 fixture 是 `rcsfgenerate.log` 层的记录，位于 `rcsfexcitation` 之后。以下改写发生在该层之前，从 fixture 出发的实现必须自行复现，不能假定 fixture 中的字段可以直接送入占据枚举：

- **预定义核 5 与 6 会被降级改写**（`rcsfexcitation.f90:78-95`）。`ncore=5` 改为 `4`，并给每个组态串追加 `4d(10,c)5s(2,c)5p(6,c)`；`ncore=6` 改为 `5`，追加 `4f(14,c)5d(10,c)6s(2,c)6p(6,c)`。因此这两种情况下相应子壳层并不属于预定义核，而是带 `c` 选择符的显式组态项。
- **活动轨道串在上述降级时被特殊补丁**（`rcsfexcitation.f90:279-323`）：`ncore5to4` 且串恰为 `4f` 时改为 `5s,4f`；`ncore6to5` 且串为 `5f`/`5f,5g`/`5g` 时前置 `6s`；`ncore6to5` 且串中没有 f 对称性时插入 `3f`（在 d 之后或 g 之前）。
- **负激发数表示关联轨道始终双占据**（`rcsfexcitation.f90:430-436`、`:632`、`:651`）。`nexc < 0` 时置 `ndouble=1`，把**空**壳层的选择符由 `*` 改写为 `d`，随后以 `iabs(nexc)` 作为激发数下传。这解释了为何 `matain.f90:255` 仅在 `org(i,j) == 0` 时才允许 `d`：`d` 只能由这条路径产生。
- **多列表以 `y` 续接**（`rcsfexcitation.f90:668-681`）。`Generate more lists?` 回答 `y` 时循环写出下一段完整输入；fixture 末行的 `n`/`y` 即该回答。


## 4. 完整整数 CSF 数据模型

### 4.1 数据层级

| 层级 | 必须保存的信息 |
|---|---|
| 全局元数据 | 格式版本、闭核定义、有序轨道定义及相对论子壳层身份、耦合顺序 |
| 占据表 | 各相对论子壳层电子数、稳定占据 ID |
| 子壳层态定义 | 2J、seniority，以及现有规则需要的其他态区分标签；若使用态 ID，必须可确定还原 |
| CSF 记录 | 占据 ID、各相关子壳层态、完整中间耦合链 |
| 对称性块 | 总 2J、宇称、CSF 数量和有序记录范围 |
| 生成任务元数据 | 来源、允许 J 集合、原版顺序标识；不必逐 CSF 重复保存 |

所有角动量使用整数 2J，避免浮点。记录不能仅靠 J 区分态；seniority 的“未显式标注”与有效数值必须有明确语义。轨道、计数、偏移和任务 ID 的位宽按已验证范围确定；大型计数和偏移采用足够的 64 位表示，并检查溢出。

### 4.2 存储策略

- 占据和固定元数据共享，避免每条 CSF 复制轨道字符串、完整占据数组和闭壳层常量。
- 使用连续分块存储和工作线程局部缓冲，避免每条 CSF 的多个堆分配。
- 在生成后组织块引用或索引，尽量避免复制全部结果。
- 最终输出时才格式化三行文本；ML 描述符从整数记录直接派生。
- 全局内存预算涵盖占据集合、结果容量冗余、调度和索引、格式化缓冲以及描述符派生临时内存。128 GB 是硬件前提，不等于进程可占满全部内存。
- 达到预算时明确失败并报告阶段和规模；磁盘回退属于后续可选能力，不作为第一版默认流程。

不预设固定的每 CSF 字节数。实现后报告真实记录大小、容量开销和峰值 RSS，分别测量完整整数表示与现有稠密描述符的内存需求。

## 5. 去重规则

去重的是重复的完整生成任务，不是把同占据的多个合法 CSF 合并为一条。

1. 每个参考组态独立应用原版的激发和占据限制。
2. 将合法占据编码为规范键，区分所有相对论子壳层，例如 `p-` 与 `p`。
3. 在相同轨道定义、耦合规则等上下文中合并重复任务；哈希只用于查找，必须比较完整键以处理碰撞。
4. 若目标 J 范围不同，明确合并允许 J 的集合；不得丢失某一路允许的生成结果。
5. 同一唯一任务的所有合法子壳层态和耦合链完整保留。

已有列表扩展或带不完整耦合集合的输入不得直接套用“占据相同即跳过”的新规则。必须先复现原版该模式的实际行为，再决定任务粒度和去重键。保持原版行为与修改其潜在缺陷是两个独立工作，不混入同一次等价迁移。

## 6. 并行策略与确定顺序

- 第一层以唯一占据及目标 J 为任务，采用动态调度。
- 对特别大的任务，按子壳层态组合或耦合链前缀进一步切分；各分支必须互斥且并集覆盖原任务。
- 避免为每一条 CSF 创建调度任务；通过批量和粒度阈值控制开销。
- 工作线程使用私有状态和结果块，避免逐条 CSF 竞争全局锁。
- 每个分支携带与原版枚举相对应的稳定顺序标识，最终复现合并和 J/P 分块后的顺序。
- 哈希表迭代顺序、任务领取顺序和完成顺序都不能决定最终 CSF 顺序。
- 第一版基于 Rust/Rayon 完成单机多核；MPI/多节点属于后续范围。

先查明原版的占据比较规则、耦合遍历顺序和分块顺序，再设计顺序键。不得假定“首次出现顺序”或普通字典排序等于原版最终顺序。

## 7. 分阶段实施

### 阶段 A：冻结原版与建立测量基线

- 完成服务器数据登记，保存不可覆盖的原版基准输出。
- 使用独立工作目录运行原版，避免固定临时文件名冲突。

验收：登记的生成输入能复现基准，重复运行结果稳定；已有差异得到解释。

当前进度：登记表已填写，两份输入记录用登记的可执行文件重跑后与基准逐字节相同，各 J/P 块数量已记录（见阶段 C）。**分阶段耗时、峰值内存和磁盘 I/O 的测量尚未进行**，§9 的性能表格仍全为待测，因此阶段 A 的验收只完成了等价性部分，基线测量部分未完成。测量应在实现优化之前补齐，否则后续无法区分收益来源。

### 阶段 B：先验证整数表示无损

- 在隔离的 GRASP 开发分支或测试副本中，保留原版枚举和查找表。
- 在原本输出 CSF 的位置捕获占据、子壳层态和耦合链的值副本，建立整数记录；不能引用后续循环会修改的数组。
- 保留原输出作为对照，建立整数表示与原始三行记录的一一对应。
- 实现整数记录到 GRASP 文本的格式化，核实子壳层态标签、空白省略和字段对齐规则。
- 测试现有真实 CSF 的解析往返，严格报告不能表示或无效的数据，不能静默填零继续验收。

验收：复杂态信息完整；整数记录格式化后的语义与原版一致。固定原版输出的格式兼容性也需验证，逐字节差异必须解释，不能掩盖记录顺序或量子数差异。

当前进度（2026-09-09）：已在 `rCSFs/src/complete_csf.rs` 建立基于连续 arena 的完整整数表示和严格编解码器，并对登记的两个真实文件完成逐字节往返验证。整数 J 文件包含 225,157 条 CSF、7 个 J/P 块，整数结构已分配容量约 27.3 MB；半整数 J 文件包含 89,786 条 CSF、2 个 J/P 块，已分配容量约 12.6 MB。该容量统计包含整数结构所拥有的堆容量，不包含分配器元数据和解析临时缓冲，因此不等于进程峰值 RSS。两者的还原文件均与输入逐字节一致。该结果验证了现有输出文件的无损表示，不代表 Rust 生成算法已与 Fortran 等价；阶段 C 尚未开始验收。

### 阶段 C：Rust 串行等价实现

- 在 rCSFs 内新增独立生成模块，逐项迁移查找表、占据约束、态枚举和耦合边界。
- 首先保持原版遍历逻辑，不同时引入所有优化。
- 对单占据、单参考和完整算例逐级比较整数记录及输出。
- 核验闭壳层、空占据、零结果、边界 J 和 seniority 等情况。

验收：支持范围内 Rust 串行结果与原版逐条一致；发生差异时能定位到占据、态组合或耦合分支。

阶段 C 子步骤进度：新增 `csf_generation::generate_csfs`，从一个明确给定的相对论占据组态枚举原版 `GEN` 的子壳层态和耦合，直接构造整数记录并按总 `2J` 分块。已迁移所有有定义的 `JKVANT/SENIOR` 表项及粒子/空穴对称使用规则，保留 `kopp1/kopp2` 的标签和省略规则；超出表项范围或记录上限明确报错。提供 TOML 开发示例与针对未修改 Fortran 源码的可重跑对照测试。详细范围见 [CSF_GENERATION.md](CSF_GENERATION.md)。

在此之上新增 `csf_generation::enumerate_occupations`，对应原版 `BLANDA`：解析 `rcsfgenerate` 交互输入记录、按 `slug.f90` 的 `varmax/varupp/varned` 上下界枚举非相对论占据、施加 `blanda.f90` 的参考宇称判据、拆分为相对论分量，并按 `TEST/LIKA` 的降序归并多个参考组态。已登记的 `e1_cc1as1` 和 `o1_cc1as1` 交互输入记录保存在 `tests/fixtures/`，其逐 J 块记录数与上表可执行文件的输出完全一致（e1 为 Even 的 7 个块共 452,373 条，o1 为 Odd 的 2 个块共 89,786 条），并作为回归基准写入测试。

以下为阶段 C 的未完成项。按对结果正确性的影响排序，前两类会在支持范围内给出错误或缺失的结果，必须先处理：

**一、当前会静默产生错误结果**

- **多列表未实现。** `from_transcript` 只解析第一段列表，`y` 之后的后续列表被直接丢弃且不报错。原版会带着 `second=.TRUE.` 再跑一轮 `blanda` 与 `merge`（`jjgen15b.f90:104-121`）。已确认原版可正常处理这类输入。在实现之前，解析器至少必须在检测到续接的 `y` 时显式失败，而不是丢弃。
- **轨道排序选择符被忽略。** `reffa.f90` 的 `*`/`r`/`s`/`u` 四种顺序全部被接受但不生效，输出将保持默认顺序。登记的两份 fixture 均为 `*`，因此未暴露。`u` 还需读取外部 `clist.ref`。

**二、当前会失败或明确拒绝**

- **预定义核 6 无法处理。** 未实现 §3.1 的 5→4 与 6→5 降级改写，`predefined_core` 直接硬编码 0..=6。`core=6` 目前报 `reference shell 6s overlaps predefined core without c selector`；`core=5` 虽能产出结果，但其核定义与原版的构造方式不同，尚未与原版对照验证。
- **负激发数未实现**，`ExcitationRequest::from_transcript` 显式报错（显式拒绝而非静默降级，行为可接受）。实现时应按 §3.1 改写空壳层选择符，而非在占据枚举内另加规则。

**三、尚未实现的模式**

- **扩展已有列表（`e`）**。需迁移 `blandc`/`blandb`/`mergeb` 这一独立路径，并读取 `clist.inp`。注意其 15000 条占据硬上限，以及 §5 关于该模式不得直接套用"占据相同即跳过"去重键的约束。
- **追加到已有列表（`a`）**。提示已在 `jjgen15b.f90:64` 注释掉，正常交互无法到达。判定为死功能，不实现，此处记录以免后续误认为遗漏。
- **Python 生成接口**。

**四、已知的实现分歧（当前登记算例未覆盖）**

- `slug.f90:56-60` 对 `l >= 5` 将占据上限压到 4，而 `Orbital::capacity()` 返回 `2 + 4l`。登记算例最高只到 g，未触发。
- `matain.f90:255` 仅在 `org(i,j) == 0` 时允许 `d` 选择符，当前实现允许任意壳层使用。按 §3.1，`d` 在原版中只能由负激发数路径产生，故该限制并非偶然。

**五、验收缺口**

- §8 要求逐条比较，当前只完成到**逐 J 块计数**一致。452,373 条与 89,786 条记录尚未与基准逐条比对占据、态标签、耦合链和顺序。这是阶段 C 的验收硬门槛，也应优先于上述功能补全，因为它能为后续所有改动提供回归保护。

### 阶段 D：提前去重与全内存结果组织

- 将参考组态的合法占据收集与耦合展开解耦，合并重复任务。
- 将顺序规则编码到任务和结果组织过程。
- 删除新实现对文本中间文件、反复 CSF 合并和重读分块的依赖。
- 明确原版辅助输出是否需要兼容；需要保留时定义其生成规则。

验收：相同唯一任务只展开一次，结果及顺序仍与阶段 C 和原版一致；默认生成路径无巨大 CSF 文本中间文件。

### 阶段 E：多核并行

- 接入 Rayon、工作线程局部块存储和动态调度。
- 根据实际任务分布加入大任务细分，验证分支无重叠和遗漏。
- 分别以 1、2、4、8 及服务器适用的更高线程数运行。

验收：不同线程数和重复运行的最终结果一致；单 J 真实大算例能利用多核。报告计算阶段及端到端加速，不能用局部加速替代整体结果。

### 阶段 F：描述符集成与产品入口

- 从完整整数记录直接派生现有未归一化三元组描述符，再复用现有归一化路径。
- 与当前“原版文本 → rCSFs 描述符”路径逐项比较，保持已有 ML 接口和维度语义。
- 完整整数表示是生成与还原的权威数据，现有描述符仅是派生特征，不能承担无损还原或完整 CSF 去重。
- 在 rCSFs 提供生成和文本导出能力；用户 CLI、配置及调度入口放在 graspkit-tools。
- 如需持久化整数表示，增加版本化格式及元数据契约，不将其混同于现有描述符 Parquet。

验收：同一组生成记录可以输出原版等价 CSF，并直接产生兼容现有管线的描述符，无需文本中转。

### 7.1 当前实施顺序

阶段划分是能力分层，不是执行次序。按当前进度，下一步的建议顺序如下，理由是先建立回归保护、再消除错误结果、最后扩展功能面：

1. **补齐逐条比对**（阶段 C 验收缺口五）。为登记的两个算例建立记录级对照，覆盖占据、态标签、耦合链、总 J、宇称和顺序。这是后续所有改动的回归基础，优先于任何功能补全。
2. **消除静默错误**（阶段 C 缺口一）。多列表与轨道排序两项在实现前，先让解析器对未支持的输入显式失败。这一步很小，但直接决定当前实现能否被信任。
3. **补齐输入层改写**（阶段 C 缺口二）。预定义核降级改写与负激发数，均按 §3.1 在输入层实现。
4. **补齐基线测量**（阶段 A 剩余部分），在引入并行或提前去重之前完成，否则无法区分收益来源。
5. **阶段 D、E**：提前去重与全内存组织，随后接入并行。
6. **扩展模式（`e`）与阶段 F**。扩展模式是独立枚举路径，需先登记其基准输入，并单独确定去重键。

每一步完成后，登记算例的逐条对照都必须仍然通过。

## 8. 正确性验收标准

所有支持模式都必须检查：

- CSF 总数与各 J/P 块数量一致。
- 每条记录的占据、子壳层态标签、完整耦合链、总 J 和宇称一致。
- CSF 的出现次数与顺序一致，不能仅比较集合而忽略重复计数。
- 文件头、轨道顺序和块顺序符合原版契约。
- 串行、并行、不同线程数与重复运行一致。
- 格式化结果可被现有读取器正确解析，具备条件时通过后续 GRASP 工具的实际读取验证。
- 相同整数记录派生的旧版描述符与现有文本解析结果一致。

集合或计数比较用于定位问题，最终验收采用逐条比较。哈希可用于快速确认已固定文件，不能替代失败时的详细差异报告。格式层是否要求字节完全一致应明确记录；物理内容和顺序一致始终是硬要求。

未支持的输入模式必须在解析阶段显式失败，不得静默丢弃或降级为近似结果。静默产出一份看似合法但内容错误的 CSF 列表，比拒绝执行的危害更大。

## 10. 仓库分工与完成条件

- 父工作区：保存本计划和跨仓库协调文档，不复制私有子仓库源代码或真实数据。
- grasp：保持原版基准可追溯；捕获整数记录的修改放在明确隔离的开发分支或副本中。开始实施前读取相关仓库指南。
- rCSFs：完整整数模型、严格编解码、生成算法、并行实现和 Rust/Python API。按本仓库指南使用其 uv 环境进行扩展开发和测试。
- graspkit-tools：面向用户的配置、CLI、调度集成及端到端入口。
- 测试和提交遵守各子仓库指南；提交时先提交修改的子仓库，再单独提交父仓库 gitlink 更新。

完成条件：登记的支持范围内，真实基准通过逐条内容与顺序对照；默认流程单遍生成并驻留内存，无反复 CSF 文本合并；单 J 多核路径通过确定性和性能验证；可由同一完整整数表示输出 CSF 文本及现有描述符；未支持的模式与资源上限有明确记录，且在解析阶段显式失败。

若目标是替代 `rcsfgenerate` 的全部功能，支持范围还须覆盖 §3.1 的输入层改写与 §7.1 第 6 项的扩展模式；仅完成新建列表路径不构成全功能等价。截至当前，最难的两部分（`GEN` 的态表、seniority 与耦合枚举，`BLANDA` 的占据枚举、宇称判据与多参考归并）已与原版逐块相符，剩余缺口集中在输入层分支与扩展模式，工作量可观但不含未解决的物理问题。
